# Release owner runbook

Draft PR: https://github.com/tayaz-maker/tariklab/pull/256. Target route: /oyna/social-engine. The checked-in game and portal can be tested as a full production build before any public change. A local static-server wrapper is not proof of site integration.

1. Freeze the source and generated assets. Record source Git tree, remote PR head, game manifest SHA-256 and generated byte checks. The connector may create a different commit object from local Git; compare the entire tree before attributing CI.
2. Match mandatory P0/P1, three browser engines, 365-day replay with resume, two continuous hours, physical low-end hardware, two independent people and full regression to their evidence. FAIL / UNVERIFIED / SKIP keep this a draft.
3. Recheck live main, open release PRs (including Boardworld), exact-head CI and any active Cloudflare rollout. Merge only this PR with an expected head; wait for successful exact-main CI. Do not change another release's traffic.
4. Use the existing authorized Cloudflare deploy hook for the verified project and production branch. Never put its URL in Git, CI output, logs or this document. Historical references to a one-use hook and Git-triggered builds do not establish that such a hook exists now. Stop if it cannot be verified.
5. Capture deployment ID, commit SHA, previous active deployment and actual production traffic from Cloudflare. Download and compare the public manifest and each served asset. On the public route run the ordinary-player `release-smoke.mjs`: real character, conversation, physical-key movement, save export and reload. A matching manifest alone is not deployment identity; a reachable route alone is not a release.
6. If production fails, coordinate the traffic lock and restore the previously recorded known-good Cloudflare deployment; verify active traffic, SHA, prior game routes and save access again. Do not delete or downgrade SOCIAL ENGINE IndexedDB data. The previous reader may deliberately reject newer storage. Keep data intact for forward recovery. No rollback ID is claimed until an actual pre-promotion deployment is recorded.
