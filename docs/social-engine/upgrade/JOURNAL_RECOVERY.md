# Bounded autosave writes

A busy browser could process short queued batches one native IndexedDB transaction at a time and miss the 15-second drain deadline. The UI now immediately combines a contiguous prefix already in the mailbox; it never waits for more work. Batch count, UTF-8 byte limits, epoch checks, pending-tail budget, CAS, overflow handling and the canonical storage codec remain enforced. No save schema change.

With the same 400 operations and one delayed writer, 40 appends became five; the recovered world was equal. On one physical M2 using the standalone Chromium SwiftShader renderer and native IndexedDB, the prior build timed out at 15.118 seconds; the new build drained the tail in 3.948 seconds and its exported world exactly matched the authoritative one. One before/after pair does not establish a percentile, unrestricted low-end performance, multi-tab recovery or a complete release. See the raw before/after records and the full stress suites. Keep real hardware, two people, endurance, remote CI, production and rollback gates open until each has independent evidence.

Full concurrent retest in this build: closing/reopening with a committed tail, the 100000-operation burst/compaction case and fatal-recovery case passed. The second-tab conflict case did not reach its conflict assertion: initial journal setup missed the 15-second deadline. This is 3/4, up from 0/4, not a clean gate. The concurrent social suite completed 8/11; three failures were recorded in combat, rumor and retirement. The ordinary player smoke on the site build and the three existing game regressions passed.
