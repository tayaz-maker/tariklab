# Save schema5 and live command journal

SOCIAL ENGINE alone uses IndexedDB `tariklab-social-engine`, database version2. Three personal slots store exact snapshots. The automatic slot stores a normalized, SHA256-checked snapshot and a bounded hash-chained operation tail. All durable promotions are atomic and compare the observed revision, epoch, cursor and hash; a stale tab cannot overwrite the new owner.

Schema5 separates immutable identity profiles from mutable records, adds rules version and per-record schema/update tick metadata, and introduces shop service reservations. Record update ticks describe the snapshot reconciliation revision. Raw in-worker objects are materialized views. Hydration validates references, ownership, types, versions and all world invariants. Sequential v1→2→3→4→5 migration operates on a copy and preserves original bytes; authentic frozen fixtures cover all four previous schemas. Unknown future versions never silently downgrade.

Canonical record JSON is gzip/base64 encoded. The envelope checks both transport bytes and expanded canonical bytes; the stored payload remains bounded at16MiB, with bounded streaming decompression capped at48MiB before parsing. Sparse transaction identity bitmaps use exact sorted positions while dense and legacy hex blocks remain supported. No completed transfer identity is discarded to meet the size budget.

The worker emits exact ordered TICK, APPLY_WHILE_PAUSED and PAUSE_CONTROL operations. Cursor advances even when a paused command does not advance game time. Batches flush at ten operations, one second, or explicit snapshot/pause. This permits a small not-yet-committed interval at sudden process termination; no claim of saving every unacknowledged millisecond is made. IndexedDB stores only acknowledged batches. Replay stops at the first invalid suffix and quarantines original bytes, then materializes the verified prefix.

The UI writer serializes appends and checkpoints. Its mailbox is capped at600 operations. On backpressure it obtains a fresh authoritative snapshot and discards only operations covered by the exact captured cursor. Repository limits are600 operations/2MiB tail/64KiB per batch; a new snapshot is requested before500 operations. A deliberate import/copy/delete of auto first stops this writer and uses CAS. Same-tick crash recovery compares verified post-quarantine cursors, not game time alone. Quota/conflict errors preserve the in-memory world and personal-slot/export options.

Evidence is separated: pure protocol replay and adversarial codec tests; actual IndexedDB atomic/quota/concurrent/corrupt/closed-tab cases; actual full UI close/reopen,100000-tick bounded burst, competing tabs and WebGL recovery. See the current exact-source reports under `artifacts/social-engine`; earlier schema results remain historical and cannot prove a later candidate.
