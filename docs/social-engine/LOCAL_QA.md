# Reproduce the local candidate without a visible window

The portable ZIP needs Node 22+ but no dependency installation. The repository uses its own locked toolchain. For the certified local package, open the ZIP, run `node start.mjs`, and use the printed address when ready. No script opens a window for the player.

For Mac QA set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to a standalone Playwright chromium-headless-shell binary and `PLAYWRIGHT_BROWSERS_PATH` to the directory containing the installed Firefox and WebKit builds. Do not opt into the native tab test on an occupied screen. Use a fresh test origin and disposable profiles; do not erase player or older-game saves.

1. `node scripts/social-engine/verify-unit.mjs` executes every isolated source test and compares the input hashes again at the end. Run the two TypeScript checks, repository lint, full `npm test`, and `node scripts/social-engine/verify-reproducible.mjs` as separate checks.
2. Build the gated site with both `VITE_PREVIEW_MODE=1` and `VITE_SOCIAL_ENGINE_PREVIEW=1`, and run the existing Wrangler local worker. `SE_ROUTE_BASE=http://127.0.0.1:8112 node scripts/social-engine/route-browser.mjs` compares served bytes and starts a character through the real site route. This is not a cloud deployment.
3. Set `SE_BASE` to the dedicated static preview. For each of chromium, firefox and webkit set `SE_BROWSER` and run `cold-start-browser.mjs`, `property-browser.mjs`, `browser.mjs`, and `persistence-browser.mjs` from `scripts/social-engine`. Use Node’s `--experimental-strip-types` flag where the harness imports game TypeScript. The Chromium UI, journal, rollback/fault, asset, resource disposal and accessibility sweeps are separate.
4. `simulate-365.mjs` runs the original seed, a full independent replay and a day-180 save/resume. `simulate-browser.mjs` compares the pure simulation across three real JS engines. The simulation's explicit source hash, not just a commit label, determines applicability. Test late-save latency using the actual day-180 fixture and keep both the busy-host result and any quieter repeats.
5. `performance.mjs` runs real fixed-step play in headless Chromium. Do not change display power settings or accelerate game time to meet a duration. If the machine sleeps, the continuity check may reject the run. Use a dedicated QA host for unresolved hardware and native-visibility tests. Process memory requires a separate collector scoped to the test's own PID tree.
6. Keep the original acceptance contract unchanged. Refresh its evidence with reconcile → refresh-contract → reconcile → export-status. Report the portable ZIP, full test scope, skipped/unverified results and external locks separately. Never promote or push on this local-only instruction.

The Mac headless shell defaults to SwiftShader and can be far slower than the actual GPU at 1080p. The opt-in `SE_WINDOWLESS_GPU=metal` is available for the multi-tab journal and integrated society/combat harnesses only when the executable is the standalone Mac headless shell. The independent `windowless-metal-profile.mjs` also confirms the renderer of the game's own WebGL context. Under concurrent software rasterization two time-sensitive checks failed; their raw results remain in `c5-history`. Both full suites were rerun on Metal. No historical failure is treated as a passing measurement.
