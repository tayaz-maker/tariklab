# SOCIAL ENGINE decisions — 2026-11-03

1. **Isolation / release lock.** Current user instructions supersede earlier autonomous deployment authorization. Branch `feature/social-engine-development`; independent directory and object database. No main push, merge, production deployment, traffic change, or other agent mutation. Explicit route is preview-only until all gates and fresh user merge approval. No existing game source edits.
2. **Clock.** Technical specification has priority: authoritative 100 ms tick. Society clock uses integer minutes, one minute per ten ticks (24 real minutes/day). GAME_DESIGN's 48-minute example is lower priority. Render never advances authoritative time; hidden tab pauses. Physics uses bounded swept substeps within fixed ticks and quantized world positions; this is documented rather than claiming a separate 60Hz authority.
3. **Population.** 100 persistent local identities plus 1,000 background citizens. Nearby render/decision cap25 initially; 100-agent renderer scenario is a benchmark, not a claim100 rendered AI must run constantly. Remaining citizens remain in authoritative state.
4. **Units.** Money integer kuruş, relations -100..100 at gameplay boundary. Society's -1000..1000 proposal is represented by this explicit lower-resolution scale. No random wall-clock inputs.
5. **Delivery.** Strict TypeScript domain and worker sources compile into isolated static assets, served inside a dedicated lazy iframe route. This matches audited TarikLab delivery while avoiding any runtime cross-game imports. New build verification script compares generated files. Existing workflows/configuration are retained.
6. **Assets.** Supplied PNGs are concept references only. Kıyıyaka's machine-readable geometry, collisions, roads and original sprite atlas are separately authored. Provenance tracked. Audio stays disabled under AGENTS.project.md; critical feedback is visual/textual.
7. **Acceptance.** All60 criteria and additional design/society obligations retained. Automated browser sessions do not substitute for two30-minute human playtests. P0 outside PASS blocks production; P1 outside PASS blocks Gold. Current release lock also independently blocks production. No READY_FOR_MERGE before all mandatory evidence.
8. **Persistence.** Envelope/revision version separated from simulation state schema. SHA256 verification, atomic slot pointers and previous-good recovery. Sequential migrations work on copies; unsupported future versions fail closed. Existing games' namespaces are never read for migration or written.
9. **Canonical records and profiles (schema5).** Save payloads now use a normalized record graph. Every persisted object has a typed path identity, `schemaVersion`, and `updatedTick`; stable domain IDs remain in record data. `updatedTick` explicitly means the authoritative tick at which that persisted revision was reconciled, not the exact last field mutation. An immutable profile table holds identity/appearance/locality and player creation attributes once; mutable person records carry only a profile reference. The worker materializes these records into its existing typed state for efficient fixed ticks. There is one persisted authority, not a second writable profile cache. Separate `rulesVersion` rejects incompatible replay rules. The decoder rejects wrong owners, dangling/cyclic/shared references, duplicate identity authority, unknown schemas/rules, unowned records and header mismatches before state validation. Original v1–v4 source bytes and migrations remain intact. Metadata is generated at snapshot boundaries, avoiding per-tick copies solely to stamp objects. Tests: record-snapshot.test.ts, services.test.ts authentic v4 migration, full codec/journal suites.
10. **Bounded navigation and scheduling.** Static district geometry uses collision/navigation graphs and cached A*; the map cannot mutate during a save, so there is no unimplemented dynamic graph invalidation event. The pending-arrival queue is sorted by minute and stable person ID. Only the bounded local population requests detailed paths; background actors keep timed travel commitments. Fixed bounded scans replace the proposed heap/spatial hash for this first district. This is an algorithm choice, not removal of population/causality/performance gates; actual 10k synthetic and current-source browser measurements remain required. High-detail renderer count and full population are reported separately.
11. **Shop services and staffing.** Published opening hours, a64-person FIFO limit and12 completions per game minute constrain both player and citizen purchases. Waiting reserves a place, never money; only the user's eventual confirmed purchase settles their transaction. Leaving/expiry/closure clears a reservation. Children commute through scheduled arrivals. Distressed employers with unsold output and low measured demand can remove one position per day, emit a causal layoff, and preserve the person's next-day job search. No crime decision follows unemployment alone. Canonical production iteration is explicitly sorted to preserve transaction order after save hydration.
12. **Rendering package.** Only SOCIAL ENGINE's build aliases locked Pixi8.21.0 through a selective entry. It retains application, scene graph, WebGL/WebGPU rendering, sprite, graphics and text registrations; native HTML controls own interaction. PNG decoding uses bounded retries and cleans partial textures on failure. The alias does not change the installed library, dependency lock or any other game's imports. Shared app/worker chunks avoid duplicating authoritative code for compatibility mode. Bundle thresholds are unchanged; byte-level reports include all generated runtime files conservatively.

13. **Long-history size and integrity.** The first schema5 day180 checkpoint failed at the unchanged16MiB transport limit. Investigation found172176 sparse meal-transfer bitmap blocks spending100MB on hexadecimal zeroes. Sparse blocks now persist exact sorted bit positions (maximum32 per block); dense blocks and every legacy hexadecimal representation remain readable. This is a collision-free set representation, not deletion of transfer identities or a probabilistic filter.4096 individual bit-address tests, legacy reads,3000-family ledger compaction/reload/retry tests and the captured day180 world prove the transformation. Schema5 canonical record bytes are gzip/base64 encoded with a checksum for the transport and a separate SHA256 over the uncompressed canonical bytes. The16MiB stored limit remains; decompression stops at the declared bound and an independent48MiB record-graph cap before JSON parsing. Old raw canonical envelopes remain readable. All new365-day and browser proofs must rerun after this correction; earlier failures are retained.
14. **IPC timing.** A projection carries a non-authoritative `performance.timeOrigin + performance.now()` send timestamp. The main thread records receipt latency separately from worker-step cost and rendering. This timestamp never enters the world, journal, RNG, hash or replay. Measurements include scheduling/structured-clone delivery cost, not merely the duration of `postMessage`. Hardware-specific limits still require their specified devices.

15. **Intersection ownership and cosmetic player age.** Signals are deterministic phases of authoritative tick on actual perpendicular directed-lane intersections. Occupancy within the junction is the exclusive reservation; it is derived from persisted vehicle positions, so restore cannot resurrect a stale second queue. Admitted vehicles clear before a new phase. Cars sharing a physical road obey clearance even when their lane IDs differ; local pedestrians receive right of way. Two visible lamps show axis phases. The life panel displays the player's current age; there is no mandatory age game-over. NPC births/deaths remain required by the higher-priority society contract. Traffic tests cover red/clearance, occupied crossings, physical shared lanes, pedestrians and exact replay.
16. **Meal transaction identity locality.** New NPC meal IDs use `meal:v5:<business>:<queueTick>:<personId>`, a one-to-one reordering of the validated reservation identity. Participants in a shared service tick now share a compact numeric-person bitmap family. Every old transfer tombstone remains retained and readable. Queue identity validators require the exact business/person prefix and a valid nonfuture tick. This reduces high-history persistence work without merging payments, changing amounts, discarding IDs, or using a probabilistic filter. The earlier180day latency failures remain evidence until a fresh long run and browser measurement prove improvement.

17. **Manual saves during automatic writes.** Real Firefox critical-flow testing exposed a manual save returning false while the periodic automatic write held the UI busy flag. Manual requests now wait in a bounded eight-request serial queue. Only background cadence is coalesced; an explicit auto-slot click retains manual semantics. Requests queued for a replaced worker/world are invalidated rather than saving another session. Tests force automatic/manual overlap, failure continuation, replacement-world rejection and saturation; browser acceptance now asserts both commit acknowledgements before loading.

18. **Responsive accelerated QA execution.** The original synchronous100000-step QA request delayed worker snapshot messages beyond the unchanged10second request timeout and failed the browser journal stress test. QA execution now yields every500 authoritative steps, suppresses regular wall-clock ticks during the burst, and preserves command/journal order at chunk boundaries. Snapshot and pause messages can run between chunks. No steps are discarded, production cadence is unchanged, and production initialization still rejects QA stepping. A pure replay comparison covers all100000steps with an interleaved command; the original browser stress test now passes4/4 with no reduced burst or relaxed assertion.
19. **Static texture registration and the shared silence gate.** The full repository suite found Pixi's unused video capability registered transitively by its broad rendering init. SOCIAL ENGINE now explicitly registers only the original image, canvas, buffer and mask implementations. No upstream library, legacy game, shared silence assertion or dependency was modified. The unchanged five silence regression tests pass against both public and built output, and all runtime gzip is237418bytes. Three-engine visual/critical checks validate the retained static sprite and text rendering.

20. **One NPC justice authority.** A regression fixture proved the leftover weekly economy fine loop could settle reported NPC cases outside the two-slot investigation queue and omit unpaid arrears. That loop is removed; only justice settles cases. Waiting in the queue also no longer counts as sixty minutes of investigation: phase `updatedAt` begins when dispatch capacity actually admits the case. Three simultaneous NPC cases now settle two after sixty minutes and the third after its own sixty-minute interval, once each. The failed-before and passed-after fixtures are retained. Current-source365day/replay/parity evidence is required again; old run hashes remain historical evidence only.

## ADR-021 — Explicit renderer atlas ownership on teardown

A real headless WebGL lifecycle audit found that destroying the per-frame textures did not destroy the two atlas textures created through Pixi Texture.from(image). The resource cache retained two image/source entries per renderer restart: five create/render/destroy cycles left10entries and10aliases. This matters when recovery recreates a renderer.

The renderer owns both atlas base textures and now destroys each with its source after disposing shared frame textures. No other game/vendor code changes. The same five-cycle browser test now returns both cache maps to their original size and removes the canvas after every cycle; double destroy remains harmless. The isolated CI includes this actual browser check. Test-only cache instrumentation is not shipped in gameplay.

A separate OS footprint sample measured674.99MiB for the occupied Chrome test process tree, above the provisional600MiB target. The teardown defect does not explain that continuous-run measurement: no repeated renderer recreation occurred in that sample. Do not claim the footprint target fixed merely because ownership tests pass. Record the process measurement and remeasure the new candidate. The old long run remains a partial baseline; a new candidate requires its own long-run evidence.

## ADR-022 — Continuous observation and texture experiments

A historical process exited successfully after 132.6 wall minutes but only 36.5 minutes of fixed simulation. Six gaps of 8.6–18.4 minutes produced far fewer ticks than the fixed rate; the cause is not proven. Its 60-minute label and 120-minute elapsed time are not credible long-duration evidence. The original samples remain intact. Independently check each minute observation, tick progression and coverage before crediting a duration. The revised harness fails closed on a gap and never issues accelerated ticks or changes host power settings. The matrix applies the same independent check retrospectively. Three regression cases include the actual rejected trace.

On an identical scripted scene, switching MSAA off reduced total Chromium process footprint from 660.8/664.3 to 605.2/603.6 MiB. The alternative trimmed 14 building and 136 actor/prop frames losslessly: 1,624,513 visible pixels preserved relative to their pivots, decoded atlas bytes 33,554,432 to 15,740,992, PNG bytes 722,916 to 320,849. But the two actual compact/no-AA process samples were 614.2 and 635.8 MiB; physical process allocation does not equal raster file size. The private responses are diagnostics, not the frozen candidate or a memory-budget PASS. All four measured overshoots of the frozen Chrome tree remain in the gate, even if another browser or later run reports lower numbers.

### ADR-023 — Stolen units, witnesses and restitution

When a shop loses stock, keep the original victim and location in the incident and give the actual item unit a unique provenance key. A purchase creates a sale; theft does not. Restitution consumes that exact unit, restores the original stock once, and keeps the case history. Witness information comes from eligible nearby observers. A remote owner does not automatically identify the suspect. Inventory counts, ledger balances, save roundtrips and forged commands have independent executable checks.

### ADR-024 — Preserve historic command meaning on schema upgrade

The first property-crime commands did not exist in schema 5. Replaying an old autosave tail under the new semantics could turn an originally rejected command into a real theft. Decode and replay with the source schema before atomically upgrading the verified baseline, retain source bytes, and compare the active record before writing. A frozen v5 fixture from the unmodified candidate includes both a rejected future command and an accepted old command. Actual IndexedDB tests check the whole tail, including compressed envelopes.

### ADR-025 — Stable in-game controls

Simulation projections arrive more often than users navigate the interface. Create HUD controls and the minimap canvas once per attached HUD; update their values in place. Keyboard focus and pointer targets now survive a projection update. A browser test holds the same control and canvas through refreshes and then uses the real map, shop and save menus.
