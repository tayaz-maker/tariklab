# PR 258 visual rework — evidence and limits

Baseline: `dc302b29344021c87382d661290ecaf454a1245d`. The prior generator used one full-footprint box, shared windows, shopfronts and one gable algorithm for almost all buildings. The replacement retains original atlas dimensions, frame pivots and the simulation's unchanged footprints, but maps building functions to six independently composed families: apartment, house, commercial, civic, workshop and warehouse. Each has distinct elevation, glazing, roof and frontage rules. Variations include balconies, shutters, rooftop plant, shop displays and awnings. Static cables, lamps and localized ground details are presentation-only.

The actor atlas now has 128 walk and 128 run cells with stable feet pivots, independent animation phases and distinct outfit silhouettes. Run selection uses measured presentation displacement rather than changing the authoritative simulation. Four recolorable vehicle silhouettes use eight directional bases. A bounded, smoothed residual rotation follows **displayed** displacement; it is visual interpolation, not a traffic fix. Player and nearby mission-person presentation are highlighted. A new HUD arrangement groups the title and status and puts the minimap beside the mission card. Time-of-day tint and night lamp glows supplement the original ambient overlay.

## Reproduce the visual comparison

Run `node scripts/social-engine/serve.mjs` on separately checked-out baseline and candidate builds, for example on ports 18231 and 18230. Then run `scripts/social-engine/visual-matched-comparison.mjs` with those ports and a headless Chromium executable. It initializes the real worker with seed 20261103, pauses and advances both runs to the same tick, and records the camera transform and player state. The default is tick 100 / 08:10; `SE_TICK=6600` gives 19:00. The saved screenshots are genuine game renders; stepping is used only to align the comparison, not to claim normal-time play. Use `SE_WIDTH` and `SE_HEIGHT` for the two desktop sizes.

`scripts/social-engine/visual-real-gameplay.mjs` records the real game canvas at normal simulation speed; `SE_CAPTURE_MODE=walking|traffic|crowd` selects three distinct 30-second-plus sessions. It captures projection samples and physical keyboard input; no actor or crowd fixture is injected. Canvas recordings intentionally exclude HTML HUD. `visual-animation-evidence.mjs` instruments rendering only and verifies actual walk, sprint and idle selections from keyboard input. `vehicle-eight-qa.mjs` uses a clearly synthetic eight-heading fixture; it does not validate traffic physics.

## Scope and remaining risks

The authoritative domain, simulation, persistence and worker sources are unchanged. In particular, overlapping vehicles/pedestrians, driver hunger and stationary positive authoritative speed remain simulation issues owned separately. Eight discrete vehicle base frames and a constrained screen rotation do not establish collision-safe or physically smooth turns. The atlas remains procedural; individual character faces, combat poses and every architectural perspective have not received hand-authored animation. The player can still be difficult to see when multiple cars and NPCs occupy the same footprint. Existing release gates, cross-browser and representative-hardware endurance evidence remain open; keep PR 258 draft and do not deploy from this visual branch.
