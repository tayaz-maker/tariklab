## Reproduced contradictions at this source revision

These are narrow Node/resolver and rendered-string reproductions on `f643910d`, not screenshots or claims that all paths fail. They should receive real-browser and saved-fixture regressions on the integration candidate after the package gate is fixed.

1. **BROKEN: false current place after intercity move.** Create an expansion life, resolve its pending opening event, then resolve `world:move:ankara`. The result succeeds; `state.expansion.world.region === "ankara"`, while the preserved Gold `state.location === "kadikoy"`. `expansion-world.mjs:233–242` correctly removes Gold `travel:` and `visit:` actions away from İstanbul, but `app.mjs:346–347,636` still passes `getCityView(state)` into `renderCityMap`; `living-ui.mjs:88–118` marks Kadıköy `current selected`, renders “Taşın burada” and labels the board İstanbul. The resource rail separately uses `currentPlace()` and says Ankara. Reproduction output: `region=ankara`, `visitActions=0`, `travelActions=0`, `mapSaysHere=true`, `current=node-kadikoy`. **Required fix:** region-aware presentation that neither marks İstanbul as the player's current place nor invents a regional district graph; retain legitimate return/travel controls and state authority.
2. **BROKEN: confirmed appointment becomes unmanageable away from İstanbul.** Create a valid `calendar:propose` personal plan for day 2, 10:00, 60 minutes, `kadikoy-park`, `subjectId=rest`, `repeat=none`; after the pending opening card is resolved it is confirmed and `getActions` exposes `calendar:cancel:cal-1`. Resolve `world:move:ankara`; the plan stays confirmed, but `adaptWorldActions` removes every `calendar:` descriptor and `resolveAction(state,'calendar:cancel:cal-1')` returns `ok:false`. It may become missed while the player cannot cancel through the ordinary action path. The engine has a separate direct path for propose/reschedule; that does **not** prove those paths are region-safe. **Required fix:** define and implement consistent intercity commitments/cancellation/availability without double booking, teleportation or silently deleting records.
3. **BROKEN: raw union ID in history.** With an eligible known partner (synthetic setup: `flags.partner='ece'`, affinity/trust 80), resolve the real `family:marry` action. Its authoritative event has `type='family-marriage'`, `subject='union:2'`, and named detail. Rendering expansion `section='world'` includes literal `union:2`: `historySubject` / `nameOf` in `expansion-ui.mjs` cannot resolve a union ID. **Required fix:** resolve an existing union to appropriate safe names or a localized neutral label; preserve stored subject and detail bytes and never show raw internal IDs as player copy.
4. **BROKEN: free badge conflicts with enterprise charge.** Start, fund and acquire a repair business through real actions; one observed `business:pause` descriptor has `cost=0` and `description='23 TL işletme kasasından. Karşılanmayan gider borca geçer.'` (`expansion-economy.mjs:989–1015`). Generic `actionCard` labels every zero `a.cost` “Ücretsiz” even though the description identifies a business-account charge and possible arrears. **Required fix:** payer-aware cost presentation; preserve one actual enterprise transaction and avoid representing it as a player cash charge.

These findings are not a request to alter save schemas or create a second authority. They must be reconciled with unchanged save, exact-replay, UI and package requirements before release.

## Structural cleanup candidates and compatibility limits

1. **Duplicate translation call — credible coordinated candidate, not yet measured here.** `expansion-ui.mjs:158–162` calls `actionCard(translateExpansionAction(a,language))`, while `app.mjs:296–297` calls `translateExpansionAction` again for any expansion action. This is duplicated live work, not duplicate simulation state. One presentation translation authority or an explicit “already localized” callback contract could remove the second pass while preserving action IDs, copy, escaping and output. However the released `7ded3aa8` `renderExpansion` already passes translated actions to its callback, so simply passing raw actions changes a public callback contract. Any edit needs explicit ownership, cached-old-module compatibility, all-locale action-card/forecast comparisons and measured full-pack effect. No claim that it will save a material number of bytes.
2. **Old renderer exports — apparently unused, not safe to delete on local-reference evidence.** `renderNeighborhoodBoard`, `renderDistrictProfile`, and `renderNpcDepth` are still public in `deep-ui.mjs:99,119,146`; current app instead uses `living-ui` city map and public NPC profile, and repository search found no current callers. But historical 2.0 commit `e458926d` app imports all three; 3.0 `c3850ff3`, 5.0 `abfb9ee5`, and released `7ded3aa8` app do not. Stable forwarders and cached older clients make unreviewed deletion or changing output unsafe. Preserve exports unless a compatibility design proves the old consumer path and release policy; measured package results must include all forwarders and assets.
3. **Multiple rendered summaries are not duplicate authority.** Dashboard, obligation rail, daybook, calendar `renderToday`, and decision desk are separate projections of current state. Some repeat time/rent/next event. Consolidation may remove duplicated display construction, but must retain discoverability on narrow screens, original action targets, disabled reasons, accessibility labels and one authoritative calendar/ledger. Do not remove the underlying systems or old save fields to save bytes.
